Features

Built differently, on purpose

Every design decision is evaluated against one goal: LLM agents writing correct code on the first attempt.

⚡

Zero ceremony

No fn, type, in, then, or with keywords. Uppercase declares types; lowercase declares values. The body follows =.

verboseTypeScript
type Shape =
  | { kind: "Circle"; r: number }
  | { kind: "Rect"; w: number; h: number }

function area(s: Shape): number {
  switch (s.kind) {
    case "Circle": return Math.PI * s.r * s.r;
    case "Rect":   return s.w * s.h;
  }
}
compactll-lang
Shape = Circle Float | Rect Float Float

area(s Shape) Float =
  match s with
  | Circle r   -> 3.14159 * r * r
  | Rect w h   -> w * h
🤖

Errors LLMs understand

All errors are short, structured, and machine-readable. One line per error, parseable by regex — no stack traces, no prose.

compiler output 
E001 12:5  TypeMismatch     expected Str[UserId] got Str
E003 15:1  NonExhaustiveMatch Shape missing:Empty
E004 20:9  UnitMismatch     Float[m] vs Float[s]
E005  7:14 TagViolation     Str[Email] != Str[UserId]
E002  8:3  UnboundVar       username

Format: EXXX line:col ErrorKind details — the agent reads the error, patches the source, recompiles. No scraping.

🎯

Multi-target codegen

Write once in ll-lang. Compile to F#, TypeScript, Python, Java 21, or C# from the same source — same semantics, idiomatic output per target.

shell 
lllc build --target fs   adts.lll  # F# discriminated unions
lllc build --target ts   adts.lll  # TypeScript sealed interfaces
lllc build --target py   adts.lll  # Python @dataclass + Union
lllc build --target java adts.lll  # Java 21 sealed interfaces
lllc build --target cs   adts.lll  # C# records + interfaces

Quickstart

Up in 60 seconds

Requires .NET 10.

1

Get the compiler

shell 
git clone https://github.com/Neftedollar/ll-lang.git
cd ll-lang
dotnet build
dotnet test   # optional: run full test suite
2

Write your first program

hello.lll 
module Hello

-- greet takes a Str, returns nothing (unit)
greet(name Str) = printfn "Hello, %s!" name

-- entry point: uppercase name, no args
Hello = greet "ll-lang"
3

Compile and run

shell 
lllc run hello.lll
# Hello, ll-lang!
4

Scaffold a multi-file project

shell 
lllc new myapp          # creates myapp/lll.toml + src/Main.lll
cd myapp
lllc build              # emits bin/fsharp/myapp.fsproj
dotnet run --project bin/fsharp/myapp.fsproj
MCP Integration

Wire it to your LLM client

ll-lang ships a built-in MCP server. Connect it to Claude Code, Cursor, or Zed — your agent gets structured tools to compile, check, and run ll-lang without parsing shell output.

claude_desktop_config.json 
{
  "mcpServers": {
    "lllc": {
      "command": "dotnet",
      "args": ["run", "--project", "/path/to/ll-lang/src/LLLangTool", "--", "mcp"]
    }
  }
}

10 MCP tools: compile_file, compile_source, check_file, check_source, run_file, list_errors, lookup_error, stdlib_search, grammar_lookup, project_info.
